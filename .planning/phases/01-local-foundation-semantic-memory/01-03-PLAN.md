# Plan 01-03: Extension Popup & Status

**Objective**: Scaffold the WXT React Chrome extension and implement the basic popup UI with Hono backend status awareness and tabbed navigation.

## Phase Reference
Phase 01: Local Foundation & Semantic Memory
Context: `.planning/phases/01-local-foundation-semantic-memory/01-CONTEXT.md`

## Requirements
- **UI-01**: Provide a Chrome extension popup with a "Start Auto-Fill" button and provider selector.
- **UI-02**: Show real-time progress panels and status indicators during form analysis and filling.
- **UI-03**: Display a user input dialog for fields with no high-confidence memory matches.

## Tasks

### 1. Scaffold WXT React Extension
- **Action**: Setup `apps/extension` with WXT and React.
- **Action**: Add Tailwind CSS for styling.
- **Action**: Configure `wxt.config.ts` for Manifest V3.
- **Verification**: `bun dev` runs extension with hot-reload in Chrome.

### 2. Implement Tabbed Popup UI
- **Action**: Build `App.tsx` with a bottom tab bar (Main, Memories, Resumes, Settings).
- **Action**: Implement Main view with large "Start Auto-Fill" button and provider dropdown.
- **Action**: Create placeholder views for Memories, Resumes, and Settings.
- **Verification**: User can navigate between all tabs in the popup.

### 3. Implement Backend Connectivity Status
- **Action**: Create `useBackendStatus.ts` hook that polls `http://localhost:3000/health`.
- **Action**: Display "● Online" (green) or "● Offline" (red) in the header based on health status.
- **Verification**: Status changes correctly when Hono server starts/stops.
