# Plan 01-02: Memory CRUD & Semantic Search

**Objective**: Create the Hono API endpoints for storing and searching semantic memories using Zvec vector similarity.

## Phase Reference
Phase 01: Local Foundation & Semantic Memory
Context: `.planning/phases/01-local-foundation-semantic-memory/01-CONTEXT.md`

## Requirements
- **MEM-01**: Store and retrieve user answers using semantic similarity (Zvec vector DB) with an 85% confidence threshold.
- **MEM-02**: Support manual editing and deletion of stored memories via a dedicated UI (this plan covers API side).
- **MEM-03**: Track memory usage and last-used timestamps to prioritize relevant answers.

## Tasks

### 1. Implement Memory Store API
- **Action**: Create `POST /api/memories` in `apps/server/src/routes/memories.ts`.
- **Action**: Use Vercel AI SDK (`embed` method) to generate 768-dim embeddings from question.
- **Action**: Store `question`, `answer`, `embedding`, `source`, `usage_count`, and `last_used` timestamps.
- **Verification**: `curl -X POST /api/memories ...` returns 201 Created and memory is in Zvec.

### 2. Implement Semantic Search API
- **Action**: Create `GET /api/memories/search` with `query` param.
- **Action**: Perform Zvec vector search with 85% fixed threshold.
- **Action**: Increment `usage_count` and update `last_used` on successful search match.
- **Verification**: `curl -X GET /api/memories/search?query="What is your email?"` returns correct memory.

### 3. Implement Memory Management API
- **Action**: Create `GET /api/memories/all` and `DELETE /api/memories/:id`.
- **Action**: Support basic pagination or sorting by `last_used`.
- **Verification**: `DELETE` successfully removes the memory from Zvec.
